From soundscape features to a queryable knowledge graph

How rows in out/data/extraction/*.pkl become graph triples, how a link-prediction model learns the HAS_REGION edge, and how a Gradio front end asks that model to label a brand-new recording.

Plan, step by step

  1. ①Schema mapping. Turn each extraction row into (subject, predicate, object) tuples — one per acoustic index plus one HAS_REGION edge.
  2. ②Build the knowledge graph. Bulk-load the tuples into a graph database.
  3. ③Train link prediction on the resulting graph (KG embedding / GNN).
  4. ④Target relation: HAS_REGION. The model predicts which Region a Sound links to.
  5. ⑤Cardinality today is 1:1 (one sound, one region) — planned to extend to one sound linking to several regions.
  6. ⑥Persist it as the graph database backing the model.
  7. ⑦Gradio interface. Upload new audio → extract features → query the model → return the inferred Region.
